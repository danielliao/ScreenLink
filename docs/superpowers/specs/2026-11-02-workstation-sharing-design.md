# ScreenLink 工作台联动与共享方案（已于 2026-11-02 确认开发）

## 用户要求

沿用现有原生 Mac 应用及配对组，iPhone 不安装应用。增加：解锁任意一台 Mac 后解锁其他设备；最近 10 秒内有鼠标或键盘活动即不自动锁屏，即使手机已离开；暂停锁屏 30 / 60 分钟等；设备间剪贴板同步；拖文件到设备名称发送，或分发全部设备。

## 拟采用的具体行为

用户以“直接做”确认按以下方案开发。具体实现与验证范围见 docs/VALIDATION.md。

### 1. 解锁联动

- 在任意已配对 Mac 上开启“本机解锁后联动其他 Mac”。实际观察到当前用户的会话从锁定变为解锁后，发起一次组内解锁；无需再点按钮或再次认证。
- 启动应用时已解锁、只唤醒黑屏、切换用户及状态未知，不算解锁事件。ScreenLink 自己发起的手机/远程解锁不再次触发联动。
- 支持跟随端发起；通过主控路由到同组其他设备，主控也作为解锁目标，设备身份去重。主控不可用时报告无法完成组联动，不伪报成功。
- 目标仍需已启用本机实验解锁、已保存本机密码并允许钥匙串和辅助功能访问。保留每次锁定最多一次密码尝试；不传播登录密码。
- 消息包含事件标识和有效期；只处理当前组的请求，重复、过期、取消及远程结果不触发新广播。主控的组转发与本机是否允许被解锁分别控制。

### 2. 鼠标 / 键盘活动保护

- 建议采用全组规则：任意在线、已解锁且已配对的 Mac 最近 10 秒有键盘、鼠标移动/点击/滚轮或触控板活动，全组暂缓 ScreenLink 的自动锁屏。
- 只检测“多久没有输入”，不记录键值、鼠标位置或输入内容。程序自己发送的锁屏/解锁事件不续期活动保护。
- 各设备向主控报送短时有效的活动状态；接收端还要在执行自动锁屏前检查自己的活动，避免网络延迟造成正在操作的设备被锁。远端报告不使用可无限续期的过期时间；掉线设备的旧状态自然到期。
- 手机离开产生的是待执行自动锁屏意图。被活动暂缓后不能丢失意图；全组连续空闲满 10 秒，且手机仍符合离开条件时，再锁屏。新活动取消已排队的自动重试；手机返回或关闭自动锁屏取消该次意图。
- 手动“锁定全部 Mac”和用户通过系统执行的锁屏照常生效。此功能控制 ScreenLink 自动锁屏，不能撤销 macOS、企业管理策略或用户直接触发的锁屏；不把已锁屏设备因鼠标活动直接解锁。
- 休眠、唤醒的自动锁屏核对也遵守暂停和近期活动规则；休眠本身并不被阻止。

### 3. 暂停自动锁屏

- 工作台和菜单栏增加“暂停 15 / 30 / 60 / 120 分钟”“恢复自动锁屏”，默认作用于当前配对组。
- 显示暂停截止时间与剩余时间、哪些在线设备已确认。主控负责分发，断线设备重连时同步当前有效暂停状态；未收到确认不显示全组成功。
- 到期恢复原有策略，重新检查手机和活动条件，不关闭或改写原有自动锁屏设置；暂停期间仍保留手机检测、剪贴板与文件传输。
- 暂停状态可跨应用重启恢复，但必须有明确截止时间，不因重复消息或时间回拨无限延长。更换配对组后清除旧组暂停。
- 手动锁屏和系统自身的锁屏仍有效。

### 4. 剪贴板同步

- 建议首版同步文字与图片，复制文件走下面的文件传输，不隐式上传本机文件路径。各 Mac 独立开启“剪贴板同步”，默认关闭，不自动读取开启前已有的剪贴板内容。
- 只在当前用户已解锁时收发；锁屏时停止读取和覆盖，不在解锁后重放锁屏期间的旧内容。临时/机密标记的剪贴板条目跳过；这不是对所有密码的自动识别保证。
- 仅向当前配对组中同样启用此功能的设备加密传输。内容不写事件日志、磁盘历史或云端；事件仅显示成功/失败及设备名。
- 使用来源标识、事件编号、变更计数与内容摘要防止循环复制；同时复制时采用确定的事件排序收敛，同一事件只应用一次。断线不缓存历史内容，恢复后只同步新的复制动作。
- 建议单次文本上限 1 MiB、图片 10 MiB；超限提示，不截断。格式首版为 UTF-8 文本与规范化 PNG，富文本按纯文本发送。

### 5. 拖放文件与分发

- 在工作台把一个或多个普通文件拖到已验证的设备名称上，立即进入发送队列；另有“发送到所有设备”拖放区域。全部指当前组内在线且启用文件接收的其他设备，离线/未开启接收的设备明确列为未发送。
- 每台接收端提供“允许接收组内文件”开关，默认关闭；开启后无需每个文件重复确认。默认保存到“下载/ScreenLink”，可选择保存目录。
- 每个目标显示进度、结果、取消和“在 Finder 中显示”。分发独立记账，一台失败不影响其他设备；不会承诺跨设备原子成功。
- 同名文件自动加序号，绝不覆盖；先写临时文件，校验完整性后再落为正式文件。取消、掉线、空间不足或校验失败清理临时内容。完成前不会打开文件；接收文件保留下载隔离标记。
- 建议首版单文件上限 2 GiB、每批 100 个文件、每设备最多 2 路并行传输；分块读写，限制内存与排队数量。目录、符号链接和特殊文件给出明确提示，不跟随外部路径。首版不自动断点续传，可重新拖入发送。
- 锁屏时不接受新的传输，已经接受的文件可继续写入指定目录；文件传输不会成为阻止锁屏的活动信号。

## 技术边界与兼容

继续使用 Swift / AppKit / SwiftUI、Network、CryptoKit，不引入云服务或手机端。现有控制协议采用 HMAC 认证且限制为 8 KiB，不能直接承载剪贴板或文件。新增独立、有大小限制的加密流传输通道与会话认证，内容和文件名均保密；具体会话密钥机制由实现阶段依据 Apple API 验证决定。认证覆盖设备、当前组、用途、传输标识、分块顺序与结束信息，防篡改和重放。

新能力先协商版本，旧版只保留原锁屏/解锁能力；不向旧版发送它不理解的活动保护自动锁屏或共享命令，不把“未支持”显示成成功。要获得全组三项锁屏联动行为，三台均需升级。

共享组密钥沿用当前信任模型：组内成员拥有组权限，不能据此证明另一台 Mac 的用户确实通过系统认证。更换组、关闭网络、关闭共享功能会撤销相关待执行请求和共享会话；取消不能删除已经完成接收的文件。

## 验证与交付

先增加行为测试再实现，覆盖：真实锁定到解锁的联动、启动不误触发、远程不循环；10 秒边界、待锁意图不丢、主控/跟随端活动、网络延迟和过期租约；暂停到期、重启和分组变更；剪贴板加密、重复与并发、锁屏和超限；文件分块、篡改、路径穿越/链接、冲突、取消、断线、磁盘不足与多目标部分失败；旧配置与旧设备兼容。

运行项目全部自动检查、原生交互检查、Release 编译及解压包签名验证。使用虚构剪贴板和临时文件测试，不读取真实剪贴板/密码或主动锁定用户电脑。真实三机权限、蓝牙、拖放与锁屏联动需现场验收。交付代码、安装包、使用说明和明确的验证范围，沿用用户之前要求的 GitHub 提交与发布方式。
